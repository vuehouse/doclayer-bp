This page explains how the DocLayer Boilerplate starter is organized. **You are not starting from an empty project**: sample docs, a landing page, and baseline configuration are already in place so you can see how it fits together before you extend it.

## Content and navigation

This file (`02.fast-track.md`) is part of the **docs** collection under `content/docs/`. Add Markdown files in the same tree and DocLayer picks them up as routes and sidebar entries.

- **Sections** - A folder such as `content/docs/02.guidelines/` becomes a sidebar group. Put a `.navigation.yml` in each section folder (`title`, `icon`).
- **Order** - Prefix files and folders with numbers (`01.`, `02.`, ...). Use tenths (`10.`, `11.`) when you need subgroups without a new top-level section.
- **Depth** - Keep at most two levels under a collection root (for example `content/docs/section/page.md`). Next level will be not picked up by the navigation.
- **Frontmatter** - Every page needs `title` and `description`. See :dl-link[$dl-docs]{label="writing content guidelines" path="/guidelines/writing-content"} for the full contract.

Collections are declared in `content.config.ts` at the project root. This boilerplate imports the module-generated list (created when you run `pnpm prepare` or `pnpm dev`). To add another collection (for example `blog`), extend that config following the :dl-link[$dl-docs]{label="collections guide" path="/guidelines/writing-content" hash="defining-custom-collection"}.

::dl-callout{type="info" title=false}

A new collection does not appear in the header until you add a link in `dl.headerNav.links`. The starter already points **Docs** at `/docs/intro`.

::

The **landing** collection lives in `content/landing/`, it is the site home route. Everything else under `content/` is driven by the collections you define.

::dl-callout{type="note" title=false}

**Authoring rules for this repo** are summarized in `content/AGENTS.md` - dedicated to the AI Agents ... not only. 😜 Prefer `Dl*` components over raw HTML when the module already provides a pattern.

::

## Project layout

:dl-prompter[content.config.ts app.config.ts pathMap env DL variables]

Below you can see the **initial project structure** that might help you navigate through, further understanding what's beneath the hood.

::dl-code

```bash
.
├── content/               # content for the application
│   ├── docs/              # docs collection (sidebar & /docs/... routes)
│   ├── landing/           # home page collection
│   └── _shared/           # reusable snippets for :dl-renderer
├── app/
│   ├── app.config.ts      # branding, UI options, path markers, etc.
│   ├── assets/
│   │   └── styles.css     # theme overrides (CSS variables)
│   └── components/
│       └── content/       # app-specific content components (optional)
├── content.config.ts      # Nuxt Content collections
├── nuxt.config.ts         # registers @vuehouse/dl, module options, etc.
└── public/                # static assets (logos, images)
```

::

## Configuration

:dl-prompter[DlRenderer shared components app components content MDC]

`app/app.config.ts` is the main place to customize this app: header and footer links, logo paths, UI options, and **path markers** for :dl-link[$dl-docs]{label="`:dl-link`" path="/components/link"}. Markers such as `$dl-docs` map to external URLs; markers such as `$docs-intro-fast-track` resolve automatically to routes under `content/`.

The full option list is in the :dl-link[$dl-docs]{label="configuration guide" path="/guidelines/configuration"}. Environment variables (`DL_*`) are documented in `.env.example`. Use them to a.o. configure application metadata.

## Content components

DocLayer turns Markdown into layout through **content components**: callouts, code blocks, links, tooltips, steppers, and more. The full catalog, props and the way on how to use them are on :dl-link[$dl-docs]{label="components guide" path="/components"}.

:dl-renderer[component]

App-only content components belong in `app/components/content/` and follow the same :dl-link[$mdc] rules as the module-based ones. See :dl-link[$dl-docs]{label="building components guide" path="/components/building"} when you outgrow built-ins.

## Theming

:dl-prompter[theming CSS variables styles.css app assets]

Theming is mostly CSS variables. `app/assets/styles.css` imports DocLayer styles and lets you override tokens in `@theme`. Uncomment the sample block in that file to try a different palette - the dev server hot-reloads them without a manual refresh.

Details: :dl-link[$dl-docs]{label="theming and customization" path="/guidelines/theming"}.
